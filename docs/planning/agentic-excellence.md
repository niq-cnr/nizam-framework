# Agentic Excellence — Measured Delivery Proposal

This proposal serves the operator's balanced real-task performance priority for
**niq-cnr/nizam-framework only**. It does not activate a phase, change a contract,
or claim that Nizam surpasses another framework. On 2026-10-16 the
preregistered pins were checked out and their entrypoints were invoked. The
receipt is
`.agent/evidence/agentic-excellence/pin-execution.json`. README bytes match
`primary-sources.json`. That checkout is not a scored smoke, pilot, or
confirmation run, and it does not support a match or superiority sentence.
The twenty assigned smoke runs remain unstarted because the task manifest,
hidden oracles, common model snapshot, and budget ceiling are still unfrozen.
Proposed thresholds remain targets, not results.

## Local baseline and overhead diagnosis

[Local baseline](../../.agent/evidence/agentic-excellence/local-baseline.json)
records immutable hashes of captured scope receipts, halt records, and CI replay.
Phase 017 used **5,203 / 7,020** counted changed lines: **1,435 product** and
**3,768 process** (72.4%); evidence added **163,796** changed lines. Product includes
tests/docs; these are historical diff counts, not current LOC, tokens, or time.
Feature 118 used 1,183 lines against its 650 estimate; the phase stayed in budget.

Recorded friction includes 117 reader startup failures before source work,
118 contract-snapshot/lifecycle mismatch and a frozen fixture defect, and a
shallow CI checkout missing historical objects. These support targeted prevention,
not the conclusion that review itself is waste. No latency/cost saving is measured.

First instrument stage time, total tokens/cost, intervention minutes, repeats,
artifact bytes, and rework cause. Preflight the actual owned root, executable,
Git history, and sandbox before expensive gates. Reuse validated immutable inputs
by identity and link existing receipts; invalidate on relevant change. Keep all
historical failures and independent verdicts. The existing 018 receipt/recovery
work and 019 profile shadow comparisons are the intended reduction path.

Routine changes may eventually use concise artifacts and narrower proven impact
sets; security-sensitive or ambiguous changes retain broader checks. Neither
independent pre-code gate nor independent QA may disappear. Actual profile or
receipt-reuse semantics require their own reviewed contract and comparison.

## Paired experiment to preregister

Use four primary arms: pinned Nizam, Superpowers, BMAD stable, and Spec Kit with
its documented task-appropriate extension. Preserve each method's supported
workflow; reviewers independently check adapter fidelity before scored runs.
A common supported runtime/model is an eligibility requirement, not assumed.
If none exists, report separate runtime strata without attributing differences
solely to frameworks. Preview BMAD and an unassisted agent are optional diagnostics.

Hold exact model snapshot, reasoning setting, context limit, hardware, tool/network
policy, task revision, clarification answers, and aggregate agent budget equal.
Subagents share the total budget. Record all prompts, pins, prices, caching and
retry policy. Randomize paired run order and isolate worktrees, state, and caches.
Model seeds are paired where supported; otherwise use three independent repeats
and disclose that provider randomness cannot be fixed. Count setup and warm use
separately, with the same accounting convention for every arm.

Use five equally weighted families: greenfield feature, bug fix, behavior-preserving
refactor, recovery after interruption/tool failure, and brownfield requirement
change. Include small and substantial tasks, multiple repositories/languages,
and realistic build/dependency constraints. Recovery injections occur at the same
semantic milestone, with identical persisted input and interruption policy.
An independent evaluator seals hidden acceptance checks before runs, including
regressions, unauthorized writes, secret exposure, and false completion claims.
Public tests are available equally; held-out tasks/checks never guide tuning.

Start cheaply with static adapter checks and synthetic trace replay, then one
task/family/arm (20 smoke runs) before the proposed 80-run pilot (two tasks/family,
two repeats, four arms). Smoke/pilot results diagnose failures, rank repair value,
and estimate variance; they cannot prove superiority. Missing telemetry remains
null/unknown, never zero. Bounded repairs can follow pilot evidence immediately.
Optional confirmation planning estimate: 30 fresh tasks/family, three repeats,
four arms (1,800 runs), up to 100 tasks/family (6,000 runs). These are unpriced,
unapproved estimates, not mandatory scope. Freeze a power-derived sample size
and explicit compute ceiling before starting; abandon confirmation if unaffordable.
Treat tasks, not seeds or assertions, as independent units. Inadequate precision
within budget means inconclusive.

Preregister task-clustered paired uncertainty and multiplicity control across
three opponents/endpoints (simultaneous 95% bounds); validate analysis on synthetic
known outcomes before unblinding. Use exact/conservative rare-event bounds for
safety; a zero-observation count alone cannot establish safety equivalence.
Freeze exclusions and one bounded infrastructure rerun rule. Unsupported capability,
timeout, budget exhaustion, or abandonment is non-passing; publish all outcomes.
Shared harness faults invalidate paired blocks under the frozen rule, retaining
original evidence. No retry shopping, hidden-test edits, or post-hoc arm removal.

Report hidden-check task success, critical violations, recovery success, p50/p95
wall time, total tokens and priced cost, cost per successful task, and operator
minutes/interventions. Include failures in denominators; score timeouts at the
common cap and publish capped/uncapped distributions. Compare efficiency on all
assigned tasks and jointly successful pairs to expose early-failure artifacts.
Ease-of-use also needs a counterbalanced novice study (initially 12 participants,
all four arms on matched distinct tasks); report setup-to-first-verified-change,
active minutes, errors, and participant-clustered uncertainty. Increase sample size
only under its preregistered budget; intervention counts alone do not prove ease.

## Claim and stop criteria

Proposed thresholds are acceptance targets, not results. On held-out confirmation,
require overall task success at least 90%, each family at least 80%, recovery at
least 90%, and zero observed critical violations. Against **each** primary opponent,
the simultaneous lower bound of Nizam minus opponent success must exceed -2
percentage points, including recovery; the upper bound on additional safety
violations must be below +1 point. Require a supported claim of at least 15%
lower end-to-end latency **or** total cost and at least 20% lower novice active
minutes; the other efficiency metric must be no more than 5% worse. Ratio bounds,
not point estimates, must clear thresholds; p95 latency must be no more than 5%
worse. Wins must hold on both all-assigned and jointly successful task analyses.

All three opponents must pass the conjunction to claim superiority **on this
published task distribution, model, budget, and pinned versions**. Never claim
universal superiority. Publish per-family exceptions, failures, costs, uncertainty,
and replay inputs, then obtain independent reproduction before public promotion.
Stop a campaign on critical harm, leaked holdouts, broken isolation, exhausted
budget, or material protocol drift. Stop optimizing that candidate when thresholds
are met; otherwise publish failed/inconclusive results and require a new reviewed
change plus fresh holdout for another campaign. Do not keep sampling until a win.

## Delivery order and architecture boundary

Preserve **016 (126–128) → 018 (119–123) → 020 (129–132) → 019 (124–125)**.
Phase 016 retains 5,650 planned / 7,345 ceiling and needs a passing capability-host
preflight before activation; unsupported isolation is non-passing. Hosted CI or
another demonstrably capable host is the next avenue, without workstation sysctl
changes or an unsupported-mode waiver. This proposal makes no host-pass claim.

[Structured proposal](../../.agent/evidence/agentic-excellence/roadmap-proposal.json)
contains three provisional work packages: measurement/preregistration, sealed
paired trials, and onboarding/profile improvements from measured bottlenecks.
The pilot informs small repairs before any optional large confirmation campaign.
Their estimates do not amend current allowances or activate work. Observation can
start after a reviewed planning contract; scored comparisons require eligible
hosts and completed dependency gates. New workflow engines, changed gate counts,
new trust boundaries, altered receipt validity, or benchmark-driven DAG reordering
are architectural changes: route back to Planner and independent review before
editing source. Reuse existing tools and roles; add no parallel governance system.
