# Publication inventory

Intended audience: public Nizam consumers, with optional package use limited to
consumers who independently have authorized private documentation-skills access.
The owner approved the following narrow boundary in this execution session by
replying "approved." to the itemized request. That approval permits these metadata
categories; it does not qualify any package or approve a release or paid execution.

| Proposed public item | Provenance | Destination | Approval and admission condition |
| --- | --- | --- | --- |
| Skill package name and version | Package owner's immutable release inventory | Public recommendation catalogue | Category approved; actual package identity must still be supplied and verified. |
| Exact source revision and inventory digest | Same package's released bytes and digest rules | Catalogue and minimal qualification summary | Category approved; only the selected release identity, no private branch history. |
| Supported contract versions | Accepted DS release contract identities | Catalogue and summary | Category approved; no schema/specification bodies included. |
| Runtime identity | Actual authorized qualification execution | Minimal summary | Category approved; no credentials, prompts or transcripts. |
| Signed qualification summary | Trusted producer's exact-pair evidence | Approved release evidence store and catalogue reference | Category approved; signing authority, signature and tested identities must be verifiable before acceptance. |
| Vendored neutral schema | Private DS contract source | None | Not approved; do not copy into public history or CI. |
| Synthetic or derived fixture | Any restricted DS source or test material | None | Not approved; synthetic derivation does not grant publication rights. |
| Package source, private specification or corpus | Private DS repository or archive | None | Not approved. |
| Raw logs, source/output diffs and transcripts | Private compatibility or behavioral run | Private evidence store only | Never upload to public jobs, PRs, artifacts or release summaries. |
| Acquisition instructions | Owner's authorized access route | Generic guidance only until specific instructions approved | Private consumer obtains artifacts through its existing authorized access; no token or private endpoint is published. |

Nizam's independently authored empty catalogue and schema contain no DS source or
restricted derivative. Empty metadata gives no execution or acquisition permission.
No private schema, fixture, source or transcript has been copied for this preparation.

## Execution, retention and trust

Default compatibility execution is private. Use an owner-approved private host with
explicit immutable package inputs and existing authorized access. The actual host,
raw-artifact location, access controls and retention duration must be recorded in the
execution packet before a run; these values have not been selected by this policy.
No public job may acquire a private package, print scoped credentials or upload raw
outputs. Mandatory core CI remains independent of documentation-skills access.
Consumers without access receive an advisory unavailable result and keep core use.

A public attestation must name the producer, tested framework source/payload and DS
package identities, inventory digest algorithm, supported contract versions, runtime,
assessed checks, limitations and outcome. Verify its signature and immutable evidence
digest through the existing trusted release mechanism and producer identity; a bare
URL, mutable tag, prose claim or schema-valid JSON is insufficient. A producer trust
binding and signed attestation are not yet supplied, so public compatibility CI and
recommendation activation remain pending. Do not invent a signing key or treat this
policy's approval as an attestation.

NF-21 additionally requires the DS-01 standalone ownership, artifact-boundary and
extension decision as actual accepted input. It has not been accepted here. The
publication category approval is recorded separately from that external prerequisite.
NF-12/13 also require accepted versioned neutral bytes and distributable conformance
fixtures; current permission explicitly excludes public vendoring of those bytes.
Private local execution may consume authorized artifacts without republishing them.

## Boundary verification before compatibility configuration

1. Compare every proposed public field with the approved inventory above. Stop any
   unapproved body, endpoint, fixture or private-derived text before staging or logging.
2. Verify authorized artifact access in the selected private environment without
   exposing credentials. Record raw-log controls and the approved retention duration.
3. Verify producer trust, signature, exact tested identities and summary digest using
   the existing trusted release route. A missing binding blocks attestation acceptance.
4. Exercise public consumers with no access: core remains usable, recommendations
   advisory, selected required assurance checks unresolved until authorized evidence.
5. Review CI dependencies: mandatory jobs contain no private checkout, package fetch,
   private token, external documentation runtime or live-model provider requirement.

These are pending execution checks for NF-16/NF-21, not a report of performed runs.
